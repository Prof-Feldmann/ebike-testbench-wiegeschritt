# Biomechanical e-bike durability test bench — out-of-the-saddle load actuation

Measurement data from the biomechanical hardware-in-the-loop e-bike test bench at
Aalen University of Applied Sciences, recorded during the endurance campaign of 2021.

This extract documents the **out-of-the-saddle load actuation** (German *Wiegeschritt*):
two electromechanical linear actuators apply a radial load to the bottom-bracket axle,
synchronised with the pedal-torque profile generated by a virtual rider model.

## ⚠ Before publishing this repository

**This dataset is not cleared for publication yet.**

The measurements were recorded on a commercial drive unit in a project with
daum electronic GmbH. The associated master's thesis carries an explicit
confidentiality notice (*Sperrvermerk*): publication or reproduction requires the
written consent of the company. The related conference paper deliberately
anonymises the specimen.

Obtain written clearance from daum electronic GmbH before making this repository
public, and agree with them what may be named (drive designation, serial number,
failure history).

**For a journal submission, deposit the cleared dataset in an archive that issues a
persistent identifier** — Zenodo, figshare or an institutional repository — and cite
the DOI in the data availability statement. A plain Git repository has no persistent
identifier and can be rewritten or deleted, which is why publishers do not accept it
as the sole location of supporting data. Linking a GitHub repository to Zenodo gives
you both: code under version control, data under DOI.

## Headline result

The control model issues one actuator stroke for every **two** pedal revolutions.
Across four segments and 17.8 h of operation:

| | |
|---|---|
| Aggregate revolutions per stroke | 1.9997 (38,401 strokes, right actuator) |
| Per-stroke median | 1.9978, IQR 0.0150 (76,791 strokes, both actuators) |
| Stroke interval, median | 1.230 s |
| Cadence during operation | 97.3 min⁻¹ |

The aggregate ratio comes from the 20 Hz signal files; the per-stroke distribution
comes from `strokes_2021-06-30.csv`, which was derived at the original 100 Hz. At
20 Hz the edge timestamps are quantised to 50 ms, which widens the per-stroke
distribution without shifting the aggregate — hence both numbers are given.

Reproduce with:

```bash
cd analysis && pip install -r requirements.txt && python verify_double_sine.py ../data
```

## Known limitations — please read before using these data

**The actuator load cells are not in this dataset.** The force-measuring cells on the
linear actuators are acquired as analog inputs on the Speedgoat real-time target and
were logged on a separate path. What this dataset contains are the drive-side torque
sensors and the digital actuator switching commands. Force data from the actuators has
to be taken from the Speedgoat recordings.

**`torque_cmd_pedal_left` / `torque_cmd_pedal_right` are set-points, not measurements.**
In the raw files these two channels carry the generic Simulink names
`Moving Average6` and `Moving Average1`. Tracing them in the block diagram shows they
originate from `Drehmoment_Vorgabe_Pedal_Links` / `_Rechts` via a `UDP Receive` block —
they are the torque commands from the rider model, smoothed by a moving average.
They have been renamed here to prevent them being mistaken for load-cell voltages.
One residual ambiguity: the model contains a second block named `Moving Average1`, fed
from `IO397 Analog Input`. The logged pair is (1, 6) while the analog-input group is
(1, 2, 3), which is why the UDP path is the attribution used here. Confirm in the
opened model if the distinction matters to your analysis.

**`distance_bench_m` is a running counter in metres, not a per-segment distance.**
It does not reset between segments and it is reset manually at intervals. Summing the
values across rows or segments overcounts badly; take positive increments instead.

**The two distance counters disagree.** Over 129 comparable runs the drive unit's own
CAN odometer reads a median of 1.087 times the bench-side counter — about 9 % higher.
The cause has not been established; the wheel circumference stored in the drive unit
is the obvious candidate. Do not treat either counter as ground truth without checking.

**Segment 5 is a standstill section.** It contains 2.3 h at zero cadence and is included
only for completeness of the session.
